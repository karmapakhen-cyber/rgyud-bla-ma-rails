# TOC tree vs PDF ས་བཅད་ཀྱི་ཟུར་མཆན། — structural comparison

## What was and was not checked

- **Checked (reliable):** each PDF entry's depth letter (ཀ=1 … མ=16), ordinal numeral and folio. These come from the PDF text layer, which is intact for labels and folios. Depth letter = tree depth − 1.
- **Not checked:** the *title wording*. The PDF's Tibetan titles are in a broken Type3 font (garbled in the text layer), and a transcription from page images by subagents came back unreliable (self-reported guesses, ⟨?⟩ everywhere). No title-level proofreading was done and **the tree was not edited**. Title proofreading needs the PDF text from another source (a clean OCR, or a re-exported PDF).
- **Page range:** the heading ས་བཅད་ཀྱི་ཟུར་མཆན། is on PDF page 245 and the list runs to page 264 (folios 26ན–179བ). Page 254 is mid-list, so the whole list was used.

## Coverage

- The PDF list has **460 entries** and covers only the tree's section **1.2** (tree nodes 1.2 to 1.2.3, 454 nodes in the tree's document order).
- The tree's section **1.1** (17 nodes, the eight introductory topics) and the whole of section **2** (about 495 nodes, 2 to 2.2.3) have **no counterpart** in this PDF list, so they could not be compared.

## Result

- **446 of 460** PDF entries have the identical decimal path in the tree (label depth and ordinal both agree).
- **14** PDF entries have no matching path in the tree (table A).
- **10** tree nodes inside the covered range have no PDF entry (table B).
- Full per-entry listing: [pdf-sachad-skeleton.tsv](pdf-sachad-skeleton.tsv).

## Assessment of the differences (verify against the page images before changing anything)

1. **PDF p.264, five entries (ཅ༢ then ཆ༣–ཆ༥, ཇ༡–ཇ༢; folios 172ན–173བ) vs tree 1.2.2.3.1.5.2–5.5.2** — *confident: PDF label typo, tree is fine.* The run ཆ༡, ཅ༢, ཆ༣, ཆ༤, ཆ༥ mixes ཅ (depth 5) into a run of ཆ (depth 6); the tree has the same five siblings (5.1–5.5) and the two children under 5.5 (ཇ༡, ཇ༢).
2. **PDF p.250, entry ཕ༣ (depth 14, 64བ) vs tree 1.2.2.2.2.2.1.2.2.7.2.3.2.3** — *likely PDF label typo.* The tree holds a sibling "གསུམ་པ་རྟགས་སོགས་སུ་འཇོག་པའི་རྒྱུ་མཚན་བསྟན་པ" at the same place and folio, with the ordinal word གསུམ་པ matching ordinal 3; the PDF label is one level deeper than the tree (ཕ, depth 14, instead of པ, depth 13), which looks like a letter typo.
3. **PDF p.261, entries ན༡, ན༢ (depth 12, folio 147ན) under the third depth-11 entry ད༣ (146བ) vs tree 1.2.2.2.2.2.4.3.2.1.2.6.1 and .6.2 ("རྒྱས་བཤད།", "གཉིས་པ་དོན་བསྡུ།")** — *possible tree error.* In the PDF the two sub-entries sit right after the third sibling and before the fourth (147བ); in the tree the node ...2.3 (དཔེ་དོན་གྱི་བྱེད་ལས།) has no children and the two sub-nodes hang under ...2.6 instead. Check the source text around folio 147ན.
4. **PDF p.260, five entries with depth 9, ordinals 1–5 (138ན–140ན) vs the tree** — *unclear.* The PDF text layer lists the sequence 9-1…9-4 and then 9-2…9-5, i.e. three entries repeated, and the tree has no children under 1.2.2.2.2.2.4.2.2. Could be duplicated lines in the PDF, or a branch the tree left out. Check page 260 and the source around folios 138ན–140ན.
5. **PDF p.251, entry ཉ༣ (68བ) vs tree-only 1.2.2.2.2.2.1.3.3.3.3** — *unclear.* The PDF has a third depth-8 sibling under 1.2.2.2.2.2.1.2 that the tree does not have; the tree-only node 1.2.2.2.2.2.1.3.3.3.3 ("གསུམ་པ་མ་རིག་བག་ཆགས་ཀྱི་སའི་སྐྱོན།") is at a different position, so the two are probably not the same item.
6. **Two paths occur twice in the PDF** (the duplicates in item 4) — a PDF-side duplication, not a tree issue.
